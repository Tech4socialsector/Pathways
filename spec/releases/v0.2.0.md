# Pathways v0.2.0

**Release date:** 2026-10-28
**Commit range:** [v0.1.0...v0.2.0](https://github.com/Tech4socialsector/Pathways/compare/v0.1.0...v0.2.0) (888f148..f0f4ae3)
**Type:** Minor release with breaking changes

## Summary

Pathways can now be installed on the same site as ERPNext. Onboarding has its own page, people who already have a login can use the candidate portal, and Master Setup forms are safer to use.

## Feature highlights

- Runs alongside ERPNext: Pathways' Designation and Employee DocTypes are renamed.
- New Onboarding page that brings verification, joinings and IT requests together.
- Existing logins get candidate portal access when they apply.
- CC and BCC when sending an appointment order.

## Module-wise changes

### Platform: ERPNext coexistence
- **Introduced:** DocTypes `Pathways Designation` and `Pathways Employee`, replacing `Designation` and `Employee`. All Link fields, the New Joiners and ERP Upload reports, and the workspace use the new names. Screens still say "Designation" and "Employee".
- **Problem addressed:** ERPNext ships DocTypes with the same names. Whichever app migrated last overwrote the other's definition.
- **Roles affected:** none directly. Developers and integrators who use these DocType names are affected.
- **Administrator action:** run `migrate`. Update any custom report, script or integration that refers to `Designation` or `Employee` for Pathways data.

### Onboarding
- **Introduced:** an Onboarding page (`/onboarding/<tab>`) with tabs for Onboarding Verification, Joinings and IT Requests. Each tab appears for users who already had access to it. The sidebar shows one Onboarding item.
- **Modified:** verification checklists moved from Documents to Onboarding. Documents now lists only application documents. Old `/joinings`, `/it-requests` and `/documents?tab=onboarding` links redirect, so links in emails already sent still work. The IT & Facilities email links to the new tab.
- **Roles affected:** Recruiter, PNCO, IT Facilities.
- **Administrator action:** none.

### Candidate portal
- **Introduced:** when someone whose email already has a login on the site applies as a guest, a background job gives them the Candidate role, links their records and, the first time only, emails them to sign in with their existing password. No password is generated or sent. Staff and disabled logins are not changed.
- **Problem addressed:** those applicants could not see their application.
- **Roles affected:** candidates.
- **Administrator action:** the new "Candidate portal login: existing account" email can be reviewed in Email Setup.

### Offers
- **Introduced:** optional CC and BCC on **Send to Candidate**, shown in the email preview and recorded in the offer history. Invalid addresses are refused before the offer changes.
- **Fixed:** email and letter previews opened behind the Send and Sign dialogs.
- **Roles affected:** Recruiter, PNCO.

### Master Setup
- **Introduced:** link dropdowns end with **Create new <master>** for System Managers. It opens the full form in a new tab, and the options refresh on return. Each list row has an edit icon (a view icon for read-only users).
- **Modified:** Position's Hiring Manager Role is hidden (saved values are kept). Scoring Rubric Template's Pass Threshold % appears only once the rubric has criteria.
- **Removed:** the "Pass/Fail Only" scoring mode.
- **Fixed:** pressing Enter in a field saved the record. Only Save, Create and Ctrl+S save now. Deleting any record from Master Setup failed on Frappe v16.
- **Roles affected:** System Manager, Pathways Admin.

### Shortlisting
- **Modified:** faculty shortlisting criteria include guidance text for the committee.
- **Roles affected:** Shortlisting Committee members.

### Applications
- **Fixed:** applying for a job with a Single Choice screening question failed.
- **Roles affected:** candidates.

## Bug fixes

- Deleting a record from Master Setup failed.
- Applying for a job with a Single Choice screening question failed.
- Email and letter previews opened behind the dialog they were opened from.
- Pressing Enter in a Master Setup form saved the record without confirmation.

## Technical changes

- DocType renames: `designation` → `pathways_designation`, `employee` → `pathways_employee` (folders, controllers and Link fields).
- Master deletion uses `frappe.desk.form.linked_with.get_linked_docs`.
- Job Opening `files_folder` field length raised to 255.
- `pathways/demo_data.py`: `bench --site <site> execute pathways.demo_data.create` builds 11 jobs at different stages with 111 applications, using fictional `@example.org` people. `pathways.demo_data.delete` removes them. Use it on test sites only.
- New email rule seeded: Candidate portal login for an existing account.

## Breaking changes

| Change | Who is affected | Action |
|---|---|---|
| `Designation` renamed to `Pathways Designation` | Custom code, reports, integrations | Update DocType references |
| `Employee` renamed to `Pathways Employee` | Custom code, reports, integrations | Update DocType references |
| "Pass/Fail Only" scoring mode removed | Rubric owners | None; the patch moves rubrics to Weighted Score |

## Deployment instructions

```bash
cd <bench>
bench --site <site> backup --with-files
cd apps/pathways && git fetch && git checkout v0.2.0 && cd ../..
bench --site <site> migrate
bench restart
```

The compiled frontend is included in this version.

### Patches run by `migrate`

| Patch | Phase | Effect |
|---|---|---|
| `rename_designation_doctype` | Pre-sync | Renames the DocType in place when no other app defines `Designation` |
| `rename_employee_doctype` | Pre-sync | Same, for `Employee` |
| `copy_shared_designations` | Post-sync | When another app owns `Designation`: copies the records Pathways uses, then restores the other app's DocType |
| `copy_shared_employees` | Post-sync | Same, for `Employee` (records with a Source Application) |
| `faculty_shortlisting_guidance` | Post-sync | Fills empty guidance on faculty shortlisting criteria |
| `seed_email_events #candidate-portal-existing-account` | Post-sync | Adds the existing-account login email |
| `drop_pass_fail_scoring_mode` | Post-sync | Moves Pass/Fail Only rubrics to Weighted Score |

## Upgrade considerations

- Take a backup first: the rename patches move database tables.
- On sites with ERPNext, check after migrate that ERPNext's Designation and Employee lists still open and that Pathways Positions show their designations.
