# Pathways v0.3.0

**Release date:** 2026-11-05
**Commit range:** [v0.2.0...v0.3.0](https://github.com/Tech4socialsector/Pathways/compare/v0.2.0...v0.3.0) (f0f4ae3..61f50b9)
**Type:** Minor release with breaking changes

## Summary

Candidates can now reply to interview invitations on the portal, and staff handle reschedule requests from one place. The Interviews page is organised by stage, the candidate portal is simpler, honorarium details for external experts go straight to Finance, and Pathways Admin can manage access without a System Manager.

## Feature highlights

- Candidates confirm, ask to reschedule or withdraw from an interview on the portal.
- Staff accept or reject reschedule requests with one action.
- Interviews page with one tab per stage and a round switch.
- New candidate portal layout with a notification bell.
- Staff Welcome email that explains each new user's roles.
- Honorarium details for external experts are emailed to the Finance team.

## Module-wise changes

### Interviews
- **Introduced:**
  - Candidate replies: **Confirm attendance**, **Request reschedule** (reason of 10–1000 characters and one to three preferred times within 60 days) or **Withdraw**. Each reply emails the recruiters (`interview_rsvp_update`). A new time from staff resets the reply.
  - Reschedule decisions: **Accept** moves the interview to a preferred time and sends an updated invite. **Reject** keeps the time and emails the candidate the reason (`reschedule_request_declined`). The candidate cannot ask again for that slot. Decisions are recorded on the interview and the application.
  - BCC on schedule, reschedule/edit and cancel emails, with checks on format, duplicates, CC/BCC overlap and a limit of 20 addresses per field.
  - Interview dialogs note that the Google Meet guest list is hidden. New Meet events are created with the guest list hidden, and existing events have it hidden when they are next updated.
- **Modified:** the Interviews page has one tab per stage (To schedule, Scheduled, Reschedule, Completed, Cancelled) and a round switch (All rounds, Round 1 (HR), Final interview). The Reschedule tab lists candidate requests first. Each open interview has a **Reschedule** button. Export is a single **Export CSV** from the selection bar, with "Select all N matching".
- **Roles affected:** Recruiter, Pathways Admin, candidates.
- **Administrator action:** review the new email rules in Email Setup.

### Applications
- **Introduced:** an **Interviews** filter (with counts) and an optional Interview column on the Applications list: No interview, Round 1 scheduled, Reschedule requested, Withdrawn from interview, Round 1 completed, Final scheduled, Final completed, Interview cancelled.
- **Modified:** the application form saves to the candidate's account 1.2 seconds after each change and shows Unsaved changes / Saving… / All changes saved. Closing, reloading or leaving the form saves the draft first. A dialog offers **Save draft and leave** or **Keep editing**. The browser's "Leave site?" warning appears only if the draft could not be saved. The submitted screen no longer shows "What happens next".
- **Modified:** dropdown options (select fields, master link search, specialisations, candidate sources, screening-question choices) are sorted A–Z, with "Other" and "Prefer not to say" last.
- **Roles affected:** candidates, Recruiter.

### Candidate portal
- **Introduced:** a sidebar with My Applications, Openings and Change password, the candidate's name, masked email and Log out. A top bar with a notification bell. On phones the menu is a slide-out drawer. Every email Pathways sends a candidate also appears as a portal notification, except login emails.
- **Introduced:** **Forgot your current password?** on Change password emails a reset link to the signed-in candidate (at most three requests per hour).
- **Removed:** status badges, stage tracker, headline banner, KPI cards and the Profile page. `/portal/profile` opens Change password. Candidates hear about progress by email.
- **Modified:** portal login emails and the Openings page describe what candidates can do on the portal.
- **Roles affected:** candidates.

### Shortlisting
- **Modified:** Shortlisting Committee setup works like the Selection Committee: search to add, a role for each member (Chairperson, Member, Subject expert, External expert, Member secretary) and a **Number of members** checked against the Settings minimum and maximum. Member roles appear on the job's Shortlisting card.
- **Roles affected:** Recruiter, Pathways Admin.

### Selection and honorarium
- **Modified:** Panel Honorarium covers external experts only. The recruitment team enters the amount, PAN, bank details (account holder, account number, bank, branch, IFSC) and attachments (PAN card, cancelled cheque or consent form, other), then sends them to the Finance team by email (`honorarium_to_finance`). IFSC codes and account numbers are validated. Internal panellists' records track only the thank-you.
- **Removed:** the honorarium approval and payment steps.
- **Modified:** reference check templates reject duplicate questions, and checks skip repeated ones.
- **Roles affected:** Recruiter, PNCO, CFO, Pathways Admin.
- **Administrator action:** add the Finance team's address under Recipients on the "Honorarium details to Finance" email in Email Setup.

### Onboarding
- **Introduced:** a Position can list its **Onboarding Documents**. New joiners for that Position are asked for those documents. If the list is empty, all active onboarding document types for the track are used. Document verifiers can add or remove a document for one new joiner from the verification checklist.
- **Roles affected:** PNCO and other document verifiers, Pathways Admin.
- **Administrator action:** optional; fill Onboarding Documents on Positions.

### Dashboard
- **Introduced:** a **JD Status** filter and column in the application drill-down (Open, Deadline Passed, Closed, Filled, Cancelled, Not Yet Advertised).

### Administration and access
- **Introduced:** **Staff Welcome** email (Email Setup › Staff & Access), sent when a staff user is created. It lists each role with a plain description, the menu sections it opens, the approval steps it takes and a set-password link. If it is turned off, Frappe's standard welcome email is sent.
- **Modified:** Pathways Admin can open Roles & Permissions and manage users, roles and Pathways permissions. Pathways Admin can also submit and cancel the Post-Interview Green Sheet, export the Communication Log and Application Status History, and manage candidates' drafts.
- **Modified:** Master Setup no longer lists Institutions, Specialisations and UGC NET Subjects. The DocTypes and data are kept, and the application form still uses them.
- **Modified:** Position **Employment Type** options are Permanent, Consultant and Contract.
- **Fixed:** all Pathways roles can read Departments. Before, only System Manager, Pathways Admin and Recruiter could.
- **Roles affected:** System Manager, Pathways Admin, all Pathways roles.

## Bug fixes

- Users with Pathways roles other than Admin and Recruiter could not read Departments.

## Security enhancements

- Candidate APIs no longer return application or offer status, and the Application's internal fields (status, outcome, eligibility, regrets) are hidden from the candidate's view.
- Pathways Admin's access to Roles & Permissions is guarded: it cannot take over non-Pathways roles, change or remove the Pathways Admin role, or remove that role from itself. Only System Managers can change the Pathways Admin role's permissions.
- The Staff Welcome email is never copied to anyone, because it carries a set-password link.
- Interview emails never blind-copy the recipient, and an address cannot be in both CC and BCC.
- Google Meet guest lists are hidden.
- Candidate password-reset requests are rate-limited.
- Interview replies are accepted only from the candidate who owns the interview, only for open future interviews, and only once per state.

## Technical changes

- **New DocType:** Position Onboarding Document (child table of Position).
- **Interview:** RSVP options Confirmed, Reschedule Requested and Withdrawn (Declined kept as an alias). New fields for reply time, reason, preferred times and reschedule decision.
- **Panel Honorarium:** fields added for Sent to Finance, bank details, PAN and attachments. `approved_by`, `approved_on`, `paid_on` and `payment_reference` removed.
- **Recruitment Email Rule:** stage option **Staff & Access**.
- **APIs:** `respond_rsvp` accepts the new replies. New: `decide_reschedule_request`, `get_application_interview_stages`, `send_my_password_reset`, `add_checklist_document`, `remove_checklist_document`, honorarium `send_to_finance`. Removed: `get_my_profile`, `update_my_profile`.
- **Hooks:** `on_session_creation` clears a candidate's temporary-password flag after a password reset.
- **Build:** the compiled frontend (`pathways/public/frontend`, `pathways/www/pathways.html`) is no longer committed. It is built at deploy time. A root `package.json` lets `bench build` run the frontend build.
- **Tests:** added for interview replies and reschedule decisions, Meet guest list, candidate notifications and Pathways Admin access.

## Breaking changes

| Change | Who is affected | Action |
|---|---|---|
| Panel Honorarium statuses are Pending, Sent to Finance and Not applicable; the approval step is removed | CFO, Recruiter, Finance | None for data (patched). Use the Honorarium page's Send to Finance. The Honorarium Approver Roles setting is no longer used |
| Compiled frontend no longer in the repository | Whoever deploys | Run `bench build --app pathways` on every deploy |
| Position Employment Type no longer offers Grant-funded | Master data owners | Change any Position that uses Grant-funded before saving it |
| Status override role moves from System Manager to Pathways Admin (if unchanged); Pathways Admin becomes an offer reviewer | Administrators | Review Pathways Settings after migrate |
| Candidate profile APIs removed | Integrations using them | Remove those calls |

## Deployment instructions

```bash
cd <bench>
bench --site <site> backup --with-files
cd apps/pathways && git fetch && git checkout v0.3.0 && cd ../..
bench setup requirements --node
bench --site <site> migrate
bench build --app pathways
bench restart
```

### Patches run by `migrate`

| Patch | Effect |
|---|---|
| `seed_email_events #staff-welcome` | Adds the Staff Welcome email rule and template |
| `seed_email_events #interview-reply` | Adds the Interview Reply email rule |
| `seed_email_events #reschedule-request-declined` | Adds the reschedule-declined email rule |
| `honorarium_to_finance` | Approved/Paid honoraria become Sent to Finance; external experts marked Not applicable go back to Pending; adds the Finance email |
| `portal_login_wording` (two runs) | Updates portal login email wording where the saved template still has the old sentences |
| `pathways_admin_full_access` | Applies the Pathways Admin grants on sites with customised permissions; adds Admin as offer reviewer; sets Admin as status override role where it was System Manager |

## Upgrade considerations

- After migrate, review the four new rules in Email Setup and add the Finance team's address to "Honorarium details to Finance".
- Check the offer reviewer roles and the status override role in Pathways Settings.
- List any Positions with Employment Type "Grant-funded" before upgrading and decide their new type.
